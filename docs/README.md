# docs/ 说明

## 文档放置规则

> **与 RAG 业务无关的开发文档，一律放 `docs/`，不要散落在项目根目录。**

**例外**（功能性要求，必须留根目录）：

| 文件 | 为什么必须在根目录 |
|---|---|
| `CLAUDE.md` | Claude Code 只从项目根加载此约定，移走即失效 |
| `README.md` | 仓库门面，约定俗成 |

---

## 这个目录是什么

**项目开发文档**——给人看的：方案、记录。与系统的运行时行为**完全无关**。

## 这个目录不是什么

⚠️ **不是 RAG 知识库的原始文本。** `docs/` 里的任何内容都不会被 RAG 系统读取、解析或向量化。

| 内容 | 位置 | 性质 |
|---|---|---|
| **项目开发文档** | `docs/`（本目录） | 给人看的，与运行无关 |
| **运行时上传数据** | `data/uploads/` | 业务数据，gitignore |
| **测试夹具** | `eval/corpus/`、`eval/corpus_synth/` | 测试用，与线上知识库无关 |
| **接口文档** | 运行时 `/docs`（FastAPI 自动生成） | OpenAPI，非本目录 |

---

## 文档地图

| 文件 | 权威范围（只答这一个问题） |
|---|---|
| `README.md` | **本说明**：文档放在哪、边界在哪 |
| `架构方案.md` | **系统现在长什么样**：定位 / 选型 / 分层 / 数据模型 / 真实链路 / 扩展点 / 已知边界 |
| `开发记录.md` | **当时为什么这么选、踩过什么坑**：搭建过程、编码结论、关键设计决策、立项期评估存档 |

> **维护约定**：每份文档都声明**自己的权威范围**；同一事实只保留**一个**来源。
> 新增文档时，先问「这份内容能不能并进上面三份之一」——不能，才新增。
