# 评测口径（Evaluation Methodology）

> **本文只回答一个问题：用什么尺子量、别人怎么复算。**
> **不回答**「本项目的分数是多少」（那是本地评测产物），也**不含**任何语料文本、题面、`anchor` 或答案。
>
> **边界**：本文是**口径**，不是**结果**。与 `架构方案.md`（系统长什么样）、
> `开发记录.md`（为什么这么选）互不重叠；凡与评测脚本冲突，**以脚本为准**。
>
> **状态**：2026-10-30 首次发布。

---

## 1. 评测要回答的四件事

| 问题 | 指标 |
|---|---|
| 该找的证据找到了吗 | 检索类：`R@K` / `AllHit@K`（§4） |
| 该答的答对了吗 | 生成类：答案是否真的答错（§5.4） |
| 不该答的拒了吗 | 拒答类：拒答正确率 ＋ **误拒率**（§5） |
| 代价多大 | 延迟分位 ＋ `>5s` 占比 ＋ token（§6） |

**不回答**：与其他系统的绝对高低比较 —— 语料不同，分数不可比。
可比的从来是**同一把尺子**，不是同一批数据（§9）。

---

## 2. 评测题的组织方式（schema）

每题 **7 个必填字段**（无答案题另有 1 个辅助字段）：

| 字段 | 说明 |
|---|---|
| `id` | 全局唯一 |
| `kind` | `single_hop` / `multi_hop` / `conflict` / `disambiguation` / `table_numeric` / `no_answer` |
| `question` | 用户会怎么问 |
| `answer` | 标准答案 —— **逐字从语料抄录**，不是凭记忆写 |
| `sources[]` | 预期出处的**文件名列表**（多跳给多个） |
| `anchors[]` | 一段**在源文件中唯一出现**的原文片段（10~30 字），可多个 |
| `should_refuse` | 是否应该拒答 |
| `bait[]` | ⚠️ **仅无答案题**：最可能被检索到的干扰文件 —— 用于诊断"是召回到了相关内容才没拒，还是压根没召回到" |

### 2.1 为什么用 `anchor` 而不是 `chunk_id`

- `chunk_id` 随**每次重灌**变化（切块参数或语料版本一改就全变）⇒ 写进题集 = **题集自己会过期**；
- `anchor` 稳定且可自证：出题时**从库里取**、入库后**回库里验**；
- 若把「抽出来的文本形态」当 `anchor`（而不是库里真实存在的片段），命中必然为 **0**。

### 2.2 命中判据

**必须锚到「块内容」**，不能「文件名对上了就算」：

> 一个检索块命中，当且仅当它的正文包含该题的某个 `anchor`。

## 3. 分层配比

| 类型 | 题数 | 这一层在问什么 |
|---|---:|---|
| 单跳事实 | 15 | 一份文档、一个事实 —— 基线能力 |
| 多跳关系 | 10 | 需要两份以上文档才能答 |
| 事实冲突 | 5 | 语料里**真有两份文档**给出不同答案 |
| 实体消歧 | 5 | 同一简称在不同文档指不同对象 |
| 表格数值 | 10 | 答案在表格里（Excel / Word / PDF 均有） |
| 无答案 | 15 | **应拒答** —— 「宁可说没有，也不乱说」的唯一直接检验 |
| **合计** | **60** | |

⚠️ **冲突类的真值**是「候选文档之间是否**真的冲突**」，**不是**「题目类型叫冲突」——
每题必须写明哪两份文档的哪两句冲突（`anchors` 给两处）。

**为什么要分层**：只报总平均会把「哪一类差」抹掉。六类必须分别报。

---

## 4. 检索类指标

| 指标 | 定义 |
|---|---|
| `R@K` | 该题**至少一个** `anchor` 所在块进入 top-K（any-hit），K ∈ {1, 3, 5} |
| `AllHit@K` | 该题**每一个** `anchor` 所在块都进入 top-K（all-hit），K ∈ {3, 5} |

**分母**：

- `R@K` 的分母 = 可评分题（**无答案题不计入检索分母**）；
- `AllHit@K` 的**主报分母 = 多 `anchor` 子集**。全部题一起报会被大量单 `anchor` 题稀释
  （那里 `AllHit@K ≡ R@K`），信号被抹平。

**只报有区分度的指标**：某指标若在基线上**恒为常数**（例如所有题都进 top-5），
它不叫指标 —— 保留显示、退出判红位。

⚠️ `K = 1` 的 `AllHit` **不报**：多 `anchor` 题在 K=1 上**结构上恒为 0**（两段证据不可能同时排第一）。

📌 `AllHit@K` 只保证**证据都进了 top-K**，是「能答」的**必要条件，不是充分条件**
（后面还有融合与生成两跳）。

---

## 5. 拒答类指标

### 5.1 三态

系统对「有没有答案」只应落进三态：

| 态 | 含义 | 处理 |
|---|---|---|
| **有答案** | 检索与生成都足以回答 | 正常作答 |
| **无答案** | 知识库里确实没有 | **拒答** |
| **无法判断** | 调用异常 / 空输出 / 输出被截断 | 按「宁可说没找到」处理，并记**错误审计** |

### 5.2 哪些出口算「拒答」

「答不上来」有多个出口，**只有表示"未找到"的出口算拒答**：

| 出口 | 算拒答？ |
|---|---|
| 回答中出现「知识库中没有找到相关信息」一类明确表述 | ✅ |
| 生成环节返回空答案（用户确实没拿到内容） | ✅ |
| 触发澄清（资料互相矛盾，请用户确认） | ❌ —— 那是「问得不清楚 / 资料打架」，不是「没有答案」 |
| 判定器失败（不是判了"不歧义"） | ❌ —— 失败 ≠ 不存在，按**无法判断**记 |

⛔ **不得用判定器的中间状态当拒答位** —— 它表达的是**歧义三态**，不是「库里有没有」。

### 5.3 必须同时报误拒率

- **拒答正确率** = 应拒的题里**确实拒了**的比例；
- **误拒率** = 不该拒的题里**被拒**的比例。

**只报拒答正确率 = 拒答越多分越高** —— 可以用「全拒」刷满。两者必须成对出现。

> 另：**误拒必须与 `R@K` 一起看** —— 若误拒题的命中名次全是「未命中」，
> 那是由**检索缺口**解释的，不是拒答阈值太紧。

### 5.4 伴随量：答案是否真的答错

若「拒答」靠模型逐字吐出某句固定表述来判定，则拒答正确率同时受两件事影响：

```
① 该拒的题没召回（要测的东西）
② 召回了但模型不肯说那句话、照样编（"听话程度"）
```

⇒ 除判定「是否拒答」外，还要看**答案是否真的答错**；两者不一致的题单独列出 ——
那正是「会编」的直接证据。

## 6. 延迟指标

- **必须报 `p50 / p90 / p95 / max` ＋ `>5s` 占比**，⛔ 不许只报平均（平均会被长尾掩盖）。
- **缓存命中会污染分布**（命中常在毫秒级）⇒ 另报**未命中请求**的同形状分位。
- 分位对应**端到端**（检索 ＋ 生成）；分段耗时单列，不混入总分位。
- 单次对照相差 **< 2 倍**不当作性能变化（噪声）。

---

## 7. 确定性 vs 抖动

| 类别 | 指标 | 抖动 |
|---|---|---|
| **检索类** | `R@K`、`AllHit@K`、名次 | 理论上 **0**（无采样；精排为确定性模型或 `temperature=0`） |
| **生成类** | 拒答、误拒、答案对错 | **有**（生成带温度） |

**先量抖动，再定阈值**：

1. **检索类**：同配置重跑 3 次 —— 逐题一致 ⇒ 阈值**零余量**（丢 1 题即告警）；
   不一致 ⇒ 先查为什么"确定性"的东西在抖，别急着留余量。
2. **生成类**：同配置重跑 5 次 —— 得到每题翻面率，余量 = **观测抖动上限**。
3. **告警线 = 基线 ∓ (抖动 ＋ 1) 题**；余量**一律按题数**，⛔ 不写百分比。

⭐ **生成类的改善不能当「变好」的证据** —— 它可能只是抖动；**检索类指标才是硬证据**。

## 8. 实验纪律（复算的前提）

1. **显式传参 ＋ 事后核实生效值** —— 配置的默认值会让"基线组"根本不是基线；
   每次实验记录**实际生效**的 `kb` / `top-k` / 模型 / 各开关。
2. **热态测量**：每组先预热 —— 冷启动的检索耗时与热态不是一个量级。
3. **每组至少重复 2 轮**，用轮间差异当**噪声地板**；小于地板的差异一律视为噪声。
4. **一次只改一个变量**；两轮之间差了两个变量 ⇒ 归因不了。
5. ⭐ **每臂只和自己的上一次比**，⛔ 不跨臂比「改进 / 退步」。
   常用四臂（只改开关，不改题）：

   | 臂 | 混合检索 | 精排 |
   |---|---|---|
   | 纯向量 | 关 | 关 |
   | 混合-only | 开 | 关 |
   | 重排-only | 关 | 开 |
   | 混合＋重排（生产默认） | 开 | 开 |

6. **同题、同参、同一时段**；跨时段运行必须说明。
7. **逐题明细写文件**，终端只刷汇总 —— 否则说不清「坏了哪几题」。

## 9. 评测集怎么提供（公开什么、不公开什么）

| | 处理 |
|---|---|
| **评测口径**（本文：schema / 指标定义 / 命中判据 / 分层配比 / 出题方法） | ✅ **公开** |
| **评测集本身**（题面 / `anchor` / 答案） | ⛔ **不入公开仓库** —— 它们抄自私有语料，等于把语料原文公开 |
| **评测产物**（逐题命中、分数、延迟） | ⛔ 不入公开仓库 |

- **按需导出**：需要可比对时，以 `jsonl` 形式双边约定提供，**导出前逐行检查**；
  **不是**「放进 GitHub」。
- **为什么**：别人没有同一份语料，本来也跑不了；送进公开仓库 = **泄漏语料，却换不来可比性**。
- ⭐ **「能对比」的真前提是同一把尺子** —— 用本文口径在**自己的语料**上建评测集，
  比的才是同一个 `R@K`。

---

## 10. 已知限制

1. **样本量仍然小**：60 题；分层后冲突 / 消歧类仅 **5 题**，**1 题 = 20%**。单题变化不足以单独下结论。
2. **标注人单一**：冲突 / 无答案类建议**双人复核**。
3. **单语料、单语言**：换语料或换题集需**重标**，分数不迁移。
4. **生成类指标有抖动**：不能当改善证据（§7）。
5. **延迟分位是单机口径**（串行或小并发），**不是服务 SLA**。

## 11. 复算三步

```bash
# 1) 准备语料（自备）与题集（按 §9 约定导入，放在本地、不入库）
export CORPUS_DIR=/path/to/your/corpus

# 2) 建库 —— 显式传入语料目录，避免默认值把库灌错
#    （--kb 用你自己的库名；下面以 rag 为例）
python eval/ingest.py --dir "$CORPUS_DIR" --kb rag

# 3) 跑评测 —— 四臂同题同参，产物落 logs/
python eval/run_layered_eval.py --kb rag --top 5
```

产物含逐题明细（名次 / 每个 `anchor` 的名次 / 是否拒答 / 答案），
可直接复算本文的全部指标。
